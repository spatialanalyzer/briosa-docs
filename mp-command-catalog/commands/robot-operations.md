## Add Robot/Machine (.SAMachine)

<span className="catalog-status catalog-status--next">Next</span>

Adds a robot or machine model from a `.SAMachine` file or embedded file. The
file is resolved by the local SpatialAnalyzer application.

## Add Robot/Machine (.ManipKin)

<span className="catalog-status catalog-status--next">Next</span>

Adds a robot or machine model from a `.ManipKin` file or embedded file. The
file is resolved by the local SpatialAnalyzer application.

## Delete Robot/Machine

<span className="catalog-status catalog-status--next">Next</span>

Deletes the selected Robot/Machine from the live SA job. Briosa intentionally
adds no dependency preflight beyond the MP command's behavior.

## Move Robot/Machine to Frame

<span className="catalog-status catalog-status--next">Next</span>

Moves the selected Robot/Machine to an SA Frame and returns the actual transform
in working coordinates. The exact MP defaults disable SA kinematics and arrival
acknowledgement.

## Move Robot/Machine through Path

<span className="catalog-status catalog-status--next">Next</span>

Moves the selected Robot/Machine through a caller-supplied Frame path. The exact
MP defaults enable SA kinematics, disable linear segments, and acknowledge
arrival. Briosa does not retain or preflight motion state.

## Move Robot/Machine to Named Destination

<span className="catalog-status catalog-status--next">Next</span>

Moves the selected Robot/Machine to a controller-defined named destination and
returns the actual transform in working coordinates. Arrival acknowledgement is
disabled by default.

## Set Robot/Machine Parameter

<span className="catalog-status catalog-status--next">Next</span>

Sets a machine-specific named parameter. Briosa passes the parameter name and
value through without maintaining a machine-specific allowlist.

## Get Robot/Machine Parameter

<span className="catalog-status catalog-status--next">Next</span>

Returns a machine-specific named parameter value. The public API uses a
Robot/Machine identity even though the exact SDK binding uses its structurally
compatible collection-instrument argument setter.

## Set Robot/Machine Model Link Parameters

<span className="catalog-status catalog-status--next">Next</span>

Sets the complete model-link configuration exposed by the MP command. Briosa
uses typed link and joint-component choices but adds no kinematic validation.
The public 6DOF Z field maps internally to the exact SDK literal
`6DPF Z Component`.

## Get Robot/Machine Model Link Parameters

<span className="catalog-status catalog-status--next">Next</span>

Returns the complete exact-target model-link output, including `Encoder Value`.
The public 6DOF Z field maps internally from the exact SDK literal
`6DPF Z Component`.

## Set Robot/Machine Base Transform

<span className="catalog-status catalog-status--next">Next</span>

Sets the selected machine's base transform relative to an SA Frame. Omitting
the transform uses the exact identity-transform default; the number of steps
defaults to `0`. Briosa adds no interpolation or kinematic preflight.

## Start Robot/Machine Interface

<span className="catalog-status catalog-status--next">Next</span>

Starts the selected machine's interface. `Interface Type` remains a raw,
machine-specific integer; its exact default `0` runs the SARobotDriver.
Simulation is disabled by default.

## Stop Robot/Machine Interface

<span className="catalog-status catalog-status--next">Next</span>

Stops the selected machine's interface without Briosa retaining its prior or
resulting interface state.

## Compute Robot/Machine Adjusted Goal Frame

<span className="catalog-status catalog-status--next">Next</span>

Creates a modified goal Frame from the original goal, previous adjusted goal,
and actual measured Frame, and returns the computed transform. The caller owns
the iterative workflow and supplies the prior result on each call; Briosa
retains no intermediate state.

## Move Robot/Machine to Joint Pose (6DOF)

<span className="catalog-status catalog-status--next">Next</span>

Moves a six-degree-of-freedom Robot/Machine using six caller-provided joint
values. Every exact MP joint default is `0.0`, and Briosa adds no range or
hardware-state preflight.

## Simulate Robot/Machine Path, Output CSV File

<span className="catalog-status catalog-status--next">Next</span>

Simulates motion through a caller-supplied Frame path and writes the resulting
joint settings to a CSV file or embedded file resolved by local SA.

## Create Robot Calibration

<span className="catalog-status catalog-status--next">Next</span>

Creates a named calibration for the selected Robot/Machine. The exact MP name
default is an empty string.

## Delete Robot Calibration

<span className="catalog-status catalog-status--next">Next</span>

Deletes the named calibration without an added dependency or active-calibration
preflight. The exact MP name default is an empty string.

## Import Poses Match to Measurements

<span className="catalog-status catalog-status--next">Next</span>

Associates poses from a CSV joint-set file with caller-supplied SA Point Names
for the selected calibration.

## Import Poses Match to Frames

<span className="catalog-status catalog-status--next">Next</span>

Associates poses from a CSV joint-set file with caller-supplied SA Frames for
the selected calibration.

## Perform Robot Calibration

<span className="catalog-status catalog-status--next">Next</span>

Calculates the selected calibration and returns the seven exact error and
robustness metrics. The SA 2026.1 SDK export marks the composite `Degrees of
Freedom` input unavailable, so Briosa intentionally omits that one input while
retaining every supported exact-target setting. `Show Interface` defaults to
`false`.

## Perform Robot Calibration (Alternate)

<span className="catalog-status catalog-status--next">Next</span>

Calculates the selected calibration with separate Base, Robot, and Tool degrees
of freedom strings and returns the same seven metrics. This is the recommended
operation when explicit DOF control is required. `Show Interface` defaults to
`false`.

## Start/Stop Robot Calibration Trapping

<span className="catalog-status catalog-status--next">Next</span>

Starts or stops calibration measurement trapping with the selected instrument.
The exact MP default is to stop. Briosa retains no trapping state.

## Set Active Robot Calibration

<span className="catalog-status catalog-status--next">Next</span>

Sets the named calibration active for the selected Robot/Machine without an
added calibration-state preflight.

## Set Robot Calibration Tool Frame

<span className="catalog-status catalog-status--next">Next</span>

Sets the calibration tool Frame relative to the machine flange. Omitting the
transform uses the exact identity-transform default.

## Set Robot Calibration Measurement Offset In Tool Frame

<span className="catalog-status catalog-status--next">Next</span>

Sets the measurement Frame relative to the calibration tool. Omitting the
transform uses the exact identity-transform default.

## Get Robot Pose for a Frame

<span className="catalog-status catalog-status--next">Next</span>

Returns the machine pose for an SA goal Frame. An empty reference pose tells SA
to use the current robot pose. The caller supplies the expected goal-pose count
because the SDK requires the output array dimension in advance.

## Get Calibration Appliance Integer Value

<span className="catalog-status catalog-status--next">Next</span>

Returns the appliance integer value at the caller-selected index offset. The
exact default is `0`; Briosa adds no bounds preflight.

## Set Calibration Appliance Integer Value

<span className="catalog-status catalog-status--next">Next</span>

Sets an appliance integer value at the caller-selected index offset. Both exact
defaults are `0`; Briosa adds no bounds preflight.

## Get Calibration Appliance Real Value

<span className="catalog-status catalog-status--next">Next</span>

Returns the appliance real value at the caller-selected index offset. The exact
default is `0`; Briosa adds no bounds preflight.

## Set Calibration Appliance Real Value

<span className="catalog-status catalog-status--next">Next</span>

Sets an appliance real value at the caller-selected index offset. The offset
and value both default to `0`; Briosa adds no bounds preflight.

## Get Calibration Appliance Data

<span className="catalog-status catalog-status--next">Next</span>

Returns the appliance real-value array. The caller supplies the expected array
length because the SDK requires the output dimension in advance. The SA 2026.1
SDK export marks `Integer Values` unavailable, so Briosa intentionally exposes
a partial real-values-only result.

## Set Calibration Appliance Data

<span className="catalog-status catalog-status--next">Next</span>

Sets the appliance real-value array, which defaults to empty. The SA 2026.1 SDK
export marks `Integer Values` unavailable, so Briosa intentionally exposes a
partial real-values-only input.
